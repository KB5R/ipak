# IPAK

Терминальный интерфейс FreeIPA на Python + Textual по локальной утверждённой спецификации `IPAK-TUI-SPEC.md` (не входит в Git). Реализованы M1–M5 с [последующими согласованиями пользователя](docs/DECISIONS.md): Users, Hosts, обе разновидности Groups, общий редактор членства, массовые операции CSV, редакторы HBAC/Sudo и локальный адаптер `ipalib`.

Интерфейс на английском. Проверены терминалы 80×24 и 120×36. Запись выполняется после обзора изменений и явного Apply; перемещение курсора, отметки и редактирование черновика не меняют FreeIPA.

## Запуск

Из корня репозитория, системным Python 3.9+:

```bash
python3 -m venv --system-site-packages .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m ipak
```

Последняя команда запускает **демо**: тестовые данные и `Demo · Not connected`, без обращения к FreeIPA. Изменения демо хранятся только до завершения процесса. Дата тестовых данных — 2026-11-08 UTC; в каталоге 63 пользователя, первый ограниченный запрос возвращает 48.

На FreeIPA-сервере с установленным системным `ipalib`:

```bash
kinit admin
.venv/bin/python -m ipak --live
```

Используются существующая конфигурация FreeIPA и текущий Kerberos ticket. Пароли подключения не записываются в проект. Проверка сертификата не отключается. Venv сохраняет доступ к системному `ipalib`; устанавливать его через pip не нужно. Единственная дополнительная прямая Python-зависимость — `textual==6.12.0`, вместе с его транзитивными зависимостями. Тесты используют стандартный `unittest` и встроенный Textual Pilot.

На предоставленной тестовой VM текущая копия находится в `/root/ipak-dev.2nqH08`:

```bash
ssh root@192.168.88.218
cd /root/ipak-dev.2nqH08
kinit admin
.venv/bin/python -m ipak --live
```

## Навигация и Users

| Клавиши | Действие |
|---|---|
| `↑↓`, `j/k` | Перемещение по загруженному списку, без запросов карточек |
| `Enter` | Открыть объект; из поля поиска — перейти к результатам |
| `Tab`, `Shift+Tab` | Переключить фокус; в редакторе членства — панель |
| `/` | Фильтр загруженного списка |
| `F2` | Явный поиск на сервере; пустой запрос возвращает обычный ограниченный список |
| `Space` | Отметить пользователя или строку селектора |
| `a`, `e` | Создать или редактировать объект, где действие доступно |
| `r` | Обновить / повторить чтение |
| `?` | Контекстная справка вне текстового поля |
| `Esc` | Закрыть поиск, вернуться или выбрать судьбу черновика |
| `q` | Выйти на верхнем уровне; сохранённые черновики требуют подтверждения |

При отметке пользователей появляются `N selected`, `u Enable`, `x Disable`, `p Reset password`, `g Add to group`, `c Clear`. Действие применяется к отметкам, включая скрытые фильтром, а не к строке под курсором. Review перечисляет точные логины. Смена раздела очищает отметки.

Карточка Users показывает имя, почту, прямые группы, сообщённые сервером связи HBAC/Sudo, комментарий `carlicense`, состояние и срок пароля. Отсутствующий срок — `Unknown`. Связи правил не являются расчётом эффективного доступа. В карточке: `e` — имя/почта/комментарий, `g` — группы, `a` — действия. Форма сохраняет только изменённые атрибуты.

При создании пользователя или сбросе пароля сервер генерирует уникальный временный пароль. Проверяется требование смены при входе; если чтение результата или проверка политики не удались, отчёт показывает `CHECK`. В результатах `p` показывает/скрывает пароли. Закрытие экрана очищает их; они не попадают в CSV, журналы или сохранённые черновики. `r` в отчёте действий повторяет только неудачные цели, когда такая команда предложена.

## Hosts, Groups и членство

Hosts: `a` создаёт FQDN с необязательными IP и описанием; `e` меняет описание; `g` в карточке открывает host groups. `d` требует подтверждения удаления. Ошибка DNS/адреса отображается как ошибка сервера. Переключателя enabled/disabled у хостов нет.

В Groups клавиши `1` / `2` переключают User Groups / Host Groups. Поддерживаются создание одной группы, изменение описания, подтверждённое удаление и прямые участники через `g` в карточке.

Общий редактор членства:

1. `Tab` переключает Members / Available. До ширины 120 колонок видна одна панель; от 120 — обе.
2. `Space` только отмечает строки. У каждой панели свои отметки, сохраняющиеся при поиске.
3. В Available `a` добавляет изменения в Pending; в Members `d` планирует удаление членства. `u` отменяет последний шаг. Косвенное членство показано отдельно и недоступно для удаления.
4. `/` в Members фильтрует локально; в Available ищет на сервере с задержкой ввода и ограниченной выдачей.
5. `Ctrl+S` открывает обзор точных добавлений/удалений. Apply выполняет их и показывает результат каждого. После частичного сбоя неудачные изменения остаются в Pending для следующего обзора.
6. `Esc` с изменениями предлагает Stay / Discard / Return (keep draft). Сохранённый черновик доступен при повторном открытии того же объекта в текущем сеансе.

## Bulk Operations

Меню: Create users, Create hosts, Disable / enable users, Reset passwords, Manage memberships. Действия над существующими пользователями переводят в Users для отметки целей; управление членством открывает выбор владельца и общий редактор.

Create users сначала предлагает явно выбрать порядок ФИО: `Surname Given name [Patronymic]` либо `Given name Surname`. Затем открывается `$EDITOR`, по умолчанию Vim. Create hosts использует тот же процесс без ФИО. CSV — UTF-8, разделитель `;`; строки примеров начинаются с `#` и никогда не создают объекты.

Шаблон пользователей:

```csv
ФИО*;Почта;Телефон;Отдел;Должность;Логин;Комментарий
# Петров Иван;ivan@example.test;;ИТ;Инженер;;Пример
```

Шаблон хостов:

```csv
FQDN*;IP;Описание
# host.example.test;;Пример
```

После выхода из редактора открывается таблица, без записи на сервер. Пустой логин генерируется как `имя.фамилия`: `Петров Иван` при выбранном порядке «фамилия имя» → `ivan.petrov`. Транслитерация детерминирована, например `ё→yo`, `ж→zh`, `х→kh`, `ц→ts`, `щ→shch`, `ю→yu`, `я→ya`; `ъ/ь` опускаются. При совпадении логинов требуется ручное исправление, суффиксы не добавляются. Неоднозначное ФИО требует заполнения Given name / Surname в таблице. Неизвестные CSV-колонки, неверная ширина строки и неподдерживаемые сервером заполненные поля не игнорируются.

- Стрелки выбирают ячейку, `Enter` редактирует её. Дополнительные колонки доступны горизонтальной прокруткой.
- `Space` отмечает строки; `g` назначает группы текущей либо отмеченным строкам через серверный селектор. Массовое назначение сохраняет индивидуальные назначения; их можно изменить отдельно.
- `a` добавляет пустую строку, `d` удаляет строки черновика, `u` возвращает удалённые строки. Уже созданные строки защищены от повторного редактирования полей создания.
- `e` снова открывает редактор с текущими значениями таблицы. Группы и результаты применения сохраняются в сеансе. При ошибке редактора сохраняются его код возврата и CSV; если файл и таблица изменились одновременно, предлагается выбрать источник.
- `Ctrl+S` проверяет строки, конфликты на сервере и группы, затем показывает Review с точными полями, группами и режимом временных паролей. Только Apply начинает создание.
- Результаты перечисляют создание и каждое членство отдельно. Для повтора закройте результаты, исправьте ошибки и снова нажмите `Ctrl+S`: созданные объекты и успешные членства пропускаются.

Черновики сохраняются в памяти текущего процесса. Временный CSV имеет права 0600; явный Discard удаляет его. Паролей в CSV нет. Завершение приложения с оставленными черновиками требует подтверждения их потери.

## HBAC / Sudo

`Enter` открывает обзор свойств, `a` в списке — новое правило. В обзоре `↑↓` выбирают свойство, `Enter` открывает редактор или селектор. `u` отменяет локальное изменение. Новое правило начинается без выбранных участников и без ALL, с желаемым состоянием Disabled.

Категории `Unconfigured`, `Selected`, `ALL` различаются явно. ALL выбирается отдельным действием и выделяется в итоговом Review. Сервисы/группы сервисов и команды/группы команд загружаются из API сервера. Sudo options — вводимые строки, проверяемые сервером; также доступны RunAs и order. Вложенный селектор возвращает только локальный выбор: его `Ctrl+S` не пишет правило.

Для сохранения всего правила нажмите `Ctrl+S` в **обзоре свойств**, проверьте цели и состояние, затем Apply. Неполное правило включить нельзя. На проверенной версии FreeIPA `*_add` создаёт правило включённым: IPAK создаёт его пустым, сразу отключает и лишь затем заполняет. Если отключение не удалось, заполнение останавливается. Изменяемое включённое правило также отключается перед изменениями; включение выполняется последним после проверки прочитанного результата. Операция не атомарна: отчёт показывает выполненные шаги, а незавершённый черновик сохраняется. Изменение правила другим клиентом требует обновления исходного состояния и нового обзора.

## Проверки

```bash
.venv/bin/python -m unittest discover -v
env -u NO_COLOR .venv/bin/python -m tools.capture_current
```

55 тестов прошли локально на Python 3.14.9 и на VM с Python 3.9.25. [Итоговый отчёт](docs/VALIDATION.md) содержит результаты, проверку настоящего FreeIPA, команды получения снимков и пошаговую ручную проверку. [Отчёт M1](docs/M1-VALIDATION.md) сохранён как история первого этапа. Сгенерированные протоколы `docs/*-local.txt`, `docs/*-vm.txt` и снимки `docs/screenshots/` остаются локальными и исключены из Git.

Сценарии ошибок демо:

```bash
.venv/bin/python -m ipak --scenario slow
.venv/bin/python -m ipak --scenario empty
.venv/bin/python -m ipak --scenario unauthenticated
.venv/bin/python -m ipak --scenario permission-denied
.venv/bin/python -m ipak --scenario connection-error
.venv/bin/python -m ipak --scenario validation-error
.venv/bin/python -m ipak --scenario detail-error
```

Интеграционный скрипт по умолчанию только читает. Запись включается отдельным флагом и допускается только для явно названного тестового сервера. Скрипт создаёт уникальные объекты `ipakcheck*`, затем удаляет их и проверяет очистку:

```bash
.venv/bin/python -m tools.integration_vm --expected-server ipa.lab.test
.venv/bin/python -m tools.integration_vm --expected-server ipa.lab.test --allow-writes
```

Модули `ipa.py`, `directory.py`, `bulk.py`, `rules.py` отвечают за API и модели; Textual-экраны используют эти сервисы. Не входят в согласованный объём: DNS-интерфейс, `host_disable`, вложенные группы, массовое создание групп и расчёт эффективного доступа.
